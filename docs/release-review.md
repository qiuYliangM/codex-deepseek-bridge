# 0.4.4 发布前检查

日期：2026-11-18。主要检查环境：Linux ARM64、Node.js 22.23.1。

## 本次修复

- 源码路径含空格时安装失败：改用 `fileURLToPath` 解析模块路径，并加入搬迁安装回归测试。
- 重新安装后 MCP 仍引用旧目录：更新已有注册中的启动命令与参数，保留其他设置及环境表。
- npm 安装后 Node 不允许处理 `node_modules` 内的 TypeScript：发布 JavaScript 运行入口，验证实际 tarball 安装。
- 网关 token 文件权限偏宽：在 POSIX 系统设为 `0600`，对已有文件也收紧权限；非回环、缺少 token 或包含用户名密码的地址在写入前拒绝。
- 损坏的配置被静默忽略：读取失败或不是 JSON 对象时停止安装，保留原内容。
- Codex 后台改名被误认为桌面改名：返回后台结果与桌面显示名称的差异，未同步时明确 `completed: false`。
- 发布内容不清晰：添加 MIT 许可证、文件白名单、标准 runner CI 和标签发布工作流；移除停用的 Hub 入口和旧验收程序。历史源码留在本机备份中，不作为当前发行版的一部分。

## 验证结果

- 自动测试：默认 16 项通过，2 项需显式配置真实客户端的测试跳过。
- 指定本机 Codex 后：17 项通过，1 项真实 DSH JavaScript 入口测试跳过。真实 Codex 测试在临时 `CODEX_HOME` 中创建并管理空会话，不发送模型 prompt。
- 安装包在独立、含空格的路径中离线安装成功；CLI 可运行，MCP 初始化及 12 个工具可列出。
- 提交前检查源码与安装包文件清单，未发现匹配常见密钥模式的凭据；安装包不包含个人配置、聊天、日志或客户端安装文件。
- 对 vendored `ws` 8.23.0 查询 GitHub 已发布的 npm 安全公告，检查时未发现匹配项。这不是完整的安全审计，也不保证未来没有新公告。

CI 另在标准 Ubuntu runner 上运行 Node.js 22.19.0 与 24.x。此文件记录本机检查；远程 CI 结果以仓库 Actions 页面为准。

## 保留的边界

桌面工程删除、旧后台工程自动合并、任意桌面标题同步、跨主机投递以及问答进程重启恢复仍未实现。桌面入口及持久化状态格式依赖客户端版本。此版本没有再次运行真实 DeepSeek 模型回传测试，不将模拟网关测试描述为模型实测。
